1. AVL TREE / RED-BLACK TREE
   Current Issue: Binary Search Tree is UNBALANCED
   - Problem: Worst-case O(n) time complexity when donors added in sorted order
   - Impact: Name-based search becomes inefficient with large datasets
   - Solution: Implement self-balancing AVL Tree or Red-Black Tree
   
   Implementation Details:
   - Replace current DonorBST class with AVLTree class
   - Add rotation functions: leftRotate(), rightRotate()
   - Add height tracking and balance factor calculation
   - Maintain O(log n) guarantee for insert/search/delete
   
   Code Structure:
   struct AVLNode {
       string donorName;
       int donorID;
       int height;
       AVLNode *left, *right;
   };
   
   Benefits:
   - Guaranteed O(log n) performance
   - No degradation with sorted input
   - Better scalability for 10,000+ donors

2. IMPROVED HASH FUNCTION
   Current Issue: Weak hash function causing excessive collisions
   - Problem: id % 10 creates only 10 slots, high collision rate
   - Impact: Long linked list chains, degraded performance
   - Solution: Implement better hash functions (division, multiplication, folding)
   
   Suggested Implementations:
   
   a) Division Method with Prime Number:
      int hashFunc(int id) {
          const int PRIME = 97;  // Prime number for better distribution
          return id % PRIME;
      }
   
   b) Multiplication Method:
      int hashFunc(int id) {
          const double A = 0.6180339887;  // Golden ratio
          return (int)(TABLE_SIZE * fmod(id * A, 1.0));
      }
   
   c) Folding Method:
      int hashFunc(int id) {
          string idStr = to_string(id);
          int sum = 0;
          for(int i = 0; i < idStr.length(); i += 2) {
              sum += stoi(idStr.substr(i, 2));
          }
          return sum % TABLE_SIZE;
      }
   
   Also Implement:
   - Dynamic resizing (rehashing) when load factor > 0.75
   - Separate chaining with balanced trees instead of linked lists
   - Double hashing for open addressing
